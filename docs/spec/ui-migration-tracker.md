### 待定：services 层的依赖边界（第二个服务块开工前定）

现行契约（`pyproject.toml`「Services stay free of Qt, plotting, SQL and UI」）禁止 `sqlite3`，而 import-linter 的 forbidden 契约默认连间接依赖也查，所以 services 实际上也不能 import `par_app.database`、`par_app.coordinator`；`par_app.protocol`、`par_app.device_hub`、`serial`、`pymodbus` 却没有被禁止。R-1-1 要求“应用层通过接口调用协议和存储”。

- 作者建议：services 定位为“纯计算 + 由调用方注入数据或接口（Protocol 类型）”，契约补禁 `par_app.protocol`、`par_app.device_hub`、`par_app.database`、`par_app.coordinator`、`serial`、`pymodbus`；需要读库或调协议的用例（DLI、导出、历史查询）由调用方取数后传入，或依赖 services 内定义的接口。
- 另一选项：允许用例层直接使用存储，则须放开 `sqlite3` 这一条。
- 需要负责人（或负责人指定的人）确认后再改契约；本块（指标显示换算）两种选项下都合规。
- 第二块（DLI 计算）开工时此项仍未裁决。DLI 块按“调用方取数后传入”实现：`build_series` 接收 `ParDatabase.dli_samples` 的行，`dli_period`/`integrate` 接收调用方读取的北京时间，services 不 import `par_app.database`、`par_app.coordinator`，所以两种选项下也都合规；契约本身未改。
- 第三块（导出）开工时此项仍未裁决。导出块同样按“调用方取数后传入”实现：服务只接收 `acquisitions_for_export` 的行与 `current_result`，不 import `par_app.database`；为此北京时间格式化函数 `format_beijing_time`（定义在 `par_app/database.py`）由 UI 作为参数传入。导出块首次从 services 引用旧模块 `par_app.math_ops`、`par_app.models`（均受 Domain 契约约束、不含 Qt/SQL），`pyproject.toml` 为这两个旧模块（及其依赖 `par_app.mccree1972_weights`）设 mypy `follow_imports = "silent"`：使用其类型标注，但不在 services 的 strict 检查中报告这些旧模块自身的问题。契约本身未改。
- 第四块（校准）开工时此项仍未裁决。校准块同样按“调用方取数后传入”实现：`calibration_available` 只接收 UI 读取的设备启用、配置、在线、故障、维护与停止状态，services 不 import `par_app.coordinator`、`par_app.device_hub`、`par_app.protocol`；校准的读写排队留在 UI，两种选项下都合规；契约本身未改。
